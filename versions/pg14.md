# PostgreSQL 14 Security Notes

## Key Security Enhancements

### 1. New Predefined Roles for Read/Write Separation
PostgreSQL 14 introduced built-in roles that eliminate the need to grant `SUPERUSER` or manually construct complex global table grants for read/write access:
- **`pg_read_all_data`**: Allows reading all tables, views, and sequences across all schemas in the cluster.
- **`pg_write_all_data`**: Allows writing (INSERT, UPDATE, DELETE) to all tables across all schemas.
- **`pg_database_owner`**: Implicit role membership representing the owner of the current database.

> **Security Implication**: Ensure these roles are granted only to dedicated backup, ETL, or reporting accounts. Audit role assignments to prevent unintended global data access.

### 2. SCRAM-SHA-256 Default Password Encryption
- `password_encryption` default changed from `md5` to `scram-sha-256`.
- Stronger protection against hash cracking, offline dictionary attacks, and connection eavesdropping.

### 3. Pipeline Mode in libpq
Allows client applications to send multiple queries in a pipeline without waiting for results after each query, reducing latency. Applications should ensure transaction boundaries and query parameterization remain strict in pipeline mode.

---

## Migration & Audit Considerations
- Verify that legacy accounts are migrated away from MD5 password hashes to SCRAM-SHA-256:
  ```sql
  SELECT rolname FROM pg_authid WHERE rolpassword LIKE 'md5%';
  ```
- Review any roles granted `pg_read_all_data` or `pg_write_all_data` to ensure least privilege compliance.
