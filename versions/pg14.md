# PostgreSQL 14 Security Notes

## Summary

PostgreSQL 14 introduced significant security improvements around role management, password hashing, and query observability. Released in September 2021.

---

## 1. New Predefined Roles

PostgreSQL 14 added three new predefined roles that reduce the need to grant `SUPERUSER` for common administrative tasks:

### `pg_read_all_data`
Grants `SELECT` on all tables, views, and sequences in all schemas across the cluster.

```sql
-- Grant to a read-only backup or analytics user
CREATE ROLE backup_reader WITH LOGIN PASSWORD 'SecurePass';
GRANT pg_read_all_data TO backup_reader;

-- Audit who holds this role
SELECT r.rolname AS member
FROM pg_auth_members m
JOIN pg_roles g ON m.roleid = g.oid AND g.rolname = 'pg_read_all_data'
JOIN pg_roles r ON m.member = r.oid;
```

> **Security Implication**: Any role granted `pg_read_all_data` can read ALL data in ALL schemas — including sensitive tables. Restrict this role to dedicated, authenticated service accounts with narrow IP restrictions in `pg_hba.conf`.

### `pg_write_all_data`
Grants `INSERT`, `UPDATE`, `DELETE` on all tables in all schemas. Even broader than `pg_read_all_data`.

```sql
-- Audit members — this should be empty or near-empty in production
SELECT r.rolname AS member
FROM pg_auth_members m
JOIN pg_roles g ON m.roleid = g.oid AND g.rolname = 'pg_write_all_data'
JOIN pg_roles r ON m.member = r.oid;
```

> **Security Implication**: This is equivalent to a global write grant. Never grant to application service accounts.

### `pg_database_owner`
Implicitly represents the owner of the current database. Useful for managing database-level objects without hardcoding role names in scripts.

## 2. SCRAM-SHA-256 as Default Password Encryption

In PostgreSQL 14, `password_encryption` defaults to `scram-sha-256` (changed from `md5` in PG13 and earlier).

```sql
-- Verify default
SHOW password_encryption;
-- Expected: scram-sha-256

-- Find accounts still using legacy MD5 hashes
SELECT rolname, LEFT(rolpassword, 10) AS hash_prefix
FROM pg_authid
WHERE rolpassword LIKE 'md5%'
  AND rolcanlogin = true;

-- Force migration: Revoke old password and reissue
-- (Roles must re-authenticate to regenerate the hash)
ALTER ROLE legacy_user PASSWORD 'NewSecurePassword';
```

> **Migration Risk**: If `pg_hba.conf` still specifies `md5` as the auth method, SCRAM-SHA-256 passwords will not work. Update `pg_hba.conf` to use `scram-sha-256` before migrating passwords.

## 3. Improved Connection Performance (Security Impact)

PostgreSQL 14 added **pipelining** support in `libpq`. While primarily a performance feature, pipelining changes how multiple queries are transmitted in a single round-trip. Ensure that application-level input validation and parameterization remain strict when using pipelining — an unparameterized pipeline could allow injection across statement boundaries.

---

## 4. `pg_hba.conf` and `pg_ident.conf` Reload Improvements

PostgreSQL 14 improved error reporting for malformed `pg_hba.conf` rules:

```sql
-- Inspect loaded rules and check for errors
SELECT * FROM pg_hba_file_rules;

-- Check for parse errors (look for error_detail column)
SELECT line_number, error
FROM pg_hba_file_rules
WHERE error IS NOT NULL;
```

---

## 5. Breaking Changes Affecting Security

| Change | Impact |
|--------|--------|
| `password_encryption = scram-sha-256` default | Legacy `md5` clients may break if `pg_hba.conf` also switches to `scram-sha-256` without password reset |
| `REINDEX CONCURRENTLY` improvements | No direct security impact |
| Server-side GZIP compression for WAL | WAL archives are compressed; ensure encryption is still applied separately |

## 6. Audit Queries for PG14 Environments

```sql
-- Full privilege audit for PG14
SELECT 
    r.rolname,
    r.rolsuper,
    r.rolcreaterole,
    r.rolcreatedb,
    r.rolcanlogin,
    r.rolbypassrls,
    r.rolpassword IS NOT NULL AS has_password,
    CASE 
        WHEN r.rolpassword LIKE 'md5%' THEN 'MD5 (WEAK - upgrade required)'
        WHEN r.rolpassword LIKE 'SCRAM%' THEN 'SCRAM-SHA-256 (OK)'
        WHEN r.rolpassword IS NULL THEN 'No password'
        ELSE 'Unknown format'
    END AS password_status,
    -- Check pg_read_all_data membership
    EXISTS (
        SELECT 1 FROM pg_auth_members m2
        JOIN pg_roles g ON m2.roleid = g.oid
        WHERE m2.member = r.oid AND g.rolname = 'pg_read_all_data'
    ) AS has_read_all_data,
    -- Check pg_write_all_data membership
    EXISTS (
        SELECT 1 FROM pg_auth_members m3
        JOIN pg_roles g ON m3.roleid = g.oid
        WHERE m3.member = r.oid AND g.rolname = 'pg_write_all_data'
    ) AS has_write_all_data
FROM pg_roles r
WHERE r.rolcanlogin = true
ORDER BY r.rolsuper DESC, r.rolname;
```

## Verification Checklist for PG14 Environments

- [ ] `password_encryption = 'scram-sha-256'` is confirmed
- [ ] No active login roles have `md5` password hashes
- [ ] `pg_hba.conf` uses `scram-sha-256` (not `md5`) for all connections
- [ ] `pg_read_all_data` is granted only to backup/analytics accounts
- [ ] `pg_write_all_data` is either unused or strictly controlled
- [ ] `pg_database_owner` usage in scripts is reviewed for security implications
