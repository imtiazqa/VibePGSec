# PostgreSQL 17 Security Notes

## Key Security Enhancements

### 1. Native Incremental Backups
PostgreSQL 17 introduced native block-level incremental backup support via `pg_basebackup --incremental` using write-ahead log summaries (`pg_combinebackup`).
- **Security Implication**: Decreases backup duration and storage overhead, making frequent disaster-recovery snapshots practical and reducing exposure windows during backup processing.

### 2. Login Event Triggers (`ON (login)`)
- Support for event triggers fired on user authentication (`EVENT TRIGGER ... ON login`).
- Allows security teams to enforce runtime access controls, session-level restrictions, IP verification, and custom audit alerts on connection establishment.

### 3. TLS / SSL Enhancements
- Enhanced TLS certificate validation controls and support for modern cipher configurations.
- Clearer status reporting for encrypted client connections.

### 4. Built-in Security & Privilege Granularity
- Improvements to predefined role delegation and fine-grained maintenance tasks without requiring superuser.

---

## Migration & Audit Considerations
- If using `login` event triggers, ensure that exceptions within the trigger do not lock out administrative accounts.
- Audit the privileges of roles creating or altering event triggers:
  ```sql
  SELECT evtname, evtevent, evtowner::regrole, evtenabled
  FROM pg_event_trigger;
  ```
