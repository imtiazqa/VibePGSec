# PostgreSQL 16 Security Notes

## Key Security Enhancements

### 1. Fundamental Overhaul of `CREATEROLE` Privilege
**Major Privilege Redesign**:
In PostgreSQL 15 and earlier, possessing `CREATEROLE` was nearly equivalent to having `SUPERUSER`, because a role with `CREATEROLE` could alter or grant membership into superuser-adjacent roles or grant itself high-privilege roles.

In PostgreSQL 16:
- A role with `CREATEROLE` cannot alter or drop superuser accounts.
- Roles can only grant membership in other roles if they hold the `ADMIN OPTION` for that target role.
- Prevents horizontal and vertical privilege escalation previously possible through the role management layer.

### 2. New Predefined System Roles
- **`pg_use_reserved_connections`**: Permits a non-superuser role to use connection slots reserved by `reserved_connections`.
- Enhanced granular assignment of monitoring permissions without granting superuser access.

### 3. Logical Replication from Standby Nodes
PostgreSQL 16 allows logical replication publications and subscriptions to read changes directly from a physical standby instance. This allows offloading replication workloads and minimizes direct read access on primary production clusters.

### 4. Client Connection Security
- Introduction of regular expression user/database matching in `pg_hba.conf` rules.
- Support for `require_auth` in client connection strings (ensuring client connects only if server asks for expected auth method such as `scram-sha-256`).

## Migration & Audit Considerations
- Audit `CREATEROLE` assignments and review which roles have `ADMIN OPTION`:
  ```sql
  SELECT roleid::regrole, member::regrole, admin_option
  FROM pg_auth_members
  WHERE admin_option = true;
  ```
