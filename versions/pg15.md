# PostgreSQL 15 Security Notes

## Key Security Enhancements

### 1. Revocation of CREATE on the `public` Schema by Default
**Major Security Milestone**:
Prior to PostgreSQL 15, the pseudo-role `PUBLIC` was granted `CREATE` and `USAGE` privileges on the `public` schema by default. This allowed any unprivileged user who could connect to a database to create objects (tables, functions, operators) in `public`, creating widespread risks of search path hijacking and trojan object execution against superusers or other roles.

Starting in PostgreSQL 15:
- Only the database owner can create objects in `public` by default.
- Users must explicitly be granted `CREATE` on schemas where they need object creation rights.

### 2. View Security: `security_invoker` Option
PostgreSQL 15 added the `security_invoker` parameter to views:
```sql
CREATE VIEW myview WITH (security_invoker = true) AS SELECT ...;
```
When enabled, permissions and Row-Level Security (RLS) policies are checked against the view caller rather than the view owner. This prevents views from accidentally bypassing underlying table RLS policies for unprivileged callers.

### 3. Server-Level Logging and Configuration Inspection
- Improved tracking of `pg_hba_file_rules` with error reporting details for broken authentication rules.
- Added `publication_tables` view visibility checks for logical replication isolation.

## Migration & Audit Considerations
- Verify whether legacy databases restored into PG 15 inadvertently restored `GRANT CREATE ON SCHEMA public TO PUBLIC`. Check with:
  ```sql
  SELECT has_schema_privilege('public', 'public', 'CREATE');
  ```
  If `true`, revoke it immediately:
  ```sql
  REVOKE CREATE ON SCHEMA public FROM PUBLIC;
  ```
