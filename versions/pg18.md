# PostgreSQL 18 Security Notes

## Key Security Enhancements

### 1. Dedicated `MAINTAIN` Privilege
PostgreSQL 18 introduces granular maintenance permissions on tables without requiring table ownership or `SUPERUSER`:
- `GRANT MAINTAIN ON table_name TO maintenance_role;`
- Permits running `VACUUM`, `ANALYZE`, `REINDEX`, `CLUSTER`, and `REFRESH MATERIALIZED VIEW` without granting read or write data access.
- Eliminates the security risk of having to grant full write or superuser access to automated maintenance/DBA scripts.

### 2. Native OAuth 2.0 / OAUTHBEARER Authentication
- Support for modern enterprise token-based authentication via OAuth 2.0 / OpenID Connect tokens directly in PostgreSQL connection protocol.
- Reduces dependence on static database passwords and simplifies central identity provider (IdP) integration.

### 3. Native UUIDv7 Generation Function
- Native `uuid_generate_v7()` / `uuidv7()` function conforming to RFC 9562.
- Provides time-ordered, non-sequential unique identifiers that prevent ID enumeration attacks (such as IDOR vulnerabilities) without external extensions.

---

## Migration & Audit Considerations
- Replace overprivileged DBA roles with the new `MAINTAIN` privilege where applicable:
  ```sql
  GRANT MAINTAIN ON ALL TABLES IN SCHEMA public TO dba_maintenance;
  ```
- Review `pg_hba.conf` for OAuth-based authentication configuration and token validation endpoints.
